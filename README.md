# 2GIS Company Parser

Парсер карточек компаний из 2ГИС по заданной категории и городу. Асинхронный сбор данных с использованием Playwright для B2B-продаж и лидогенерации.

## Описание

Инструмент для автоматизированного сбора контактных данных компаний из справочника 2ГИС. Результат: структурированные CSV и Excel файлы с названиями, адресами, телефонами, сайтами, рейтингами и часами работы. Применение: формирование баз для холодных звонков, email-рассылок, анализа конкурентов.

## Ключевые особенности

- Асинхронная архитектура на базе Playwright и asyncio
- Прямая инкрементальная пагинация через URL параметры
- Обязательная интеграция прокси для обхода блокировок 2ГИС
- Три способа настройки прокси: аргументы командной строки, переменные окружения, конфигурационный файл
- Адаптивные селекторы с fallback-логикой для устойчивости к изменениям DOM
- Экспорт в CSV и Excel с автоматическим форматированием колонок
- Детальное логирование всех операций
- Обработка HTTP 429/403 с автоматическими повторами и паузами

## Требования

- Python 3.10 или выше
- pip для установки зависимостей
- Chromium браузер для Playwright
- HTTP/HTTPS прокси для масштабирования

## Настройка прокси

Прокси обязательны для массового сбора. 2ГИС агрессивно блокирует IP при превышении лимита запросов.

### Способ 1: Аргументы командной строки (рекомендуется)

```bash
python run_2gis_parser.py \
  --url "https://2gis.ru/kazan/search/автосервис" \
  --proxy http://user:pass@proxy1.com:8080 \
  --proxy http://proxy2.com:3128
```

Можно указать несколько прокси через повторение параметра `--proxy`.

### Способ 2: Переменные окружения

Для одного прокси:

```bash
export HTTP_PROXY=http://user:pass@proxy.com:8080
python run_2gis_parser.py --url "https://2gis.ru/kazan/search/автосервис"
```

Для нескольких прокси (через запятую):

```bash
export PROXY_LIST="http://proxy1.com:8080,http://user:pass@proxy2.com:3128"
python run_2gis_parser.py --url "https://2gis.ru/kazan/search/автосервис"
```

### Способ 3: Конфигурационный файл

Откройте файл `config_2gis.py` и добавьте прокси в секцию `PROXY_CONFIG`:

```python
PROXY_CONFIG = {
    "enabled": True,
    "proxies": [
        "http://user:pass@proxy1.example.com:8080",
        "http://proxy2.example.com:3128",
        "http://192.168.1.100:8888",
    ],
    "rotate": True,
    "timeout": 30,
}
```

### Поддерживаемые форматы

- `http://ip:port`
- `http://user:pass@ip:port`
- `https://ip:port`
- `https://user:pass@ip:port`

Ротация прокси включена по умолчанию. Парсер автоматически переключается между прокси при каждом запросе.

### Проверка прокси

Перед запуском парсера проверьте доступность прокси:

```bash
curl -x http://proxy:port http://2gis.ru
```

Если прокси требует аутентификацию:

```bash
curl -x http://user:pass@proxy:port http://2gis.ru
```

## Конфигурация

### Параметры командной строки

| Параметр | Описание | Значение по умолчанию |
|----------|----------|----------------------|
| `--url` | URL категории на 2ГИС (обязательный) | - |
| `--max-companies` | Максимальное количество компаний | 0 (без ограничений) |
| `--max-pages` | Максимальное количество страниц | 0 (без ограничений) |
| `--no-detail` | Не открывать детальные страницы | False |
| `--output` | Директория для результатов | output_2gis |
| `--proxy` | Прокси (можно указать несколько раз) | - |
| `--resume` | Продолжить с места остановки | False |
| `--parallel N` | Запустить N параллельных worker'ов | - (последовательный режим) |
| `--mode` | Режим сбора: full, quick, detail | full |

### Параметры в config_2gis.py

**BROWSER_CONFIG** - настройки браузера:
- `headless`: режим без GUI (True для production, False для отладки)
- `viewport`: разрешение окна браузера
- `user_agent`: строка User-Agent для имитации реального браузера

**TIMEOUTS** - таймауты в миллисекундах:
- `page_load`: 45000 (загрузка страницы)
- `navigation`: 30000 (переход между страницами)
- `element_wait`: 20000 (ожидание элемента)
- `network_idle`: 15000 (ожидание сети)

**DELAYS** - задержки в секундах:
- `min_click` / `max_click`: 3.0 / 6.0 (между запросами)
- `min_scroll` / `max_scroll`: 1.0 / 3.0 (при прокрутке)
- `min_page` / `max_page`: 3.0 / 6.0 (между страницами)

**PARSING_CONFIG** - параметры парсинга:
- `max_companies`: лимит компаний (0 = без ограничений)
- `max_pages`: лимит страниц (0 = без ограничений)
- `open_detail_page`: открывать детальные страницы (True/False)
- `retry_attempts`: количество повторов при ошибке

## Resume функция (продолжение с места остановки)

Парсер поддерживает сохранение прогресса и продолжение работы после сбоя или остановки.

### Использование

Включите флаг `--resume` при запуске:

```bash
python run_2gis_parser.py \
  --url "https://2gis.ru/kazan/search/автосервис" \
  --resume
```

### Как это работает

1. Парсер сохраняет URL каждой обработанной компании в файл `output_2gis/progress.json`
2. При повторном запуске с флагом `--resume` пропускает уже собранные компании
3. Прогресс сохраняется каждые 10 компаний и после каждой страницы
4. При сбое или остановке (Ctrl+C) можно продолжить с того же места

### Примеры использования

Начать сбор с сохранением прогресса:

```bash
python run_2gis_parser.py \
  --url "https://2gis.ru/moscow/search/ресторан" \
  --max-companies 1000 \
  --resume
```

Продолжить после сбоя:

```bash
# Парсер остановился на 347 компании
# Просто запустите ту же команду снова
python run_2gis_parser.py \
  --url "https://2gis.ru/moscow/search/ресторан" \
  --max-companies 1000 \
  --resume
# Парсер пропустит первые 347 и продолжит с 348-й
```

Без флага `--resume` парсер работает как обычно (без сохранения прогресса).

## Двухфазный сбор (Quick + Detail режимы)

Парсер поддерживает двухфазный режим сбора для максимальной гибкости и скорости.

### Режимы работы

**Full (по умолчанию)** - полный сбор за один проход:
- Собирает все данные сразу (карточки + детальные страницы)
- Производительность: ~570 компаний/час
- Использование: `python run_2gis_parser.py --url "..." --mode full`

**Quick** - быстрый сбор только из карточек:
- Собирает только базовые данные из поисковой выдачи (без открытия детальных страниц)
- Данные: название, адрес, категория, рейтинг, отзывы, URL
- Производительность: ~2000 компаний/час (в 3-4 раза быстрее)
- Результат: `quick_results.json` и `companies_2gis_quick.csv`
- Использование: `python run_2gis_parser.py --url "..." --mode quick`

**Detail** - добор детальных данных:
- Читает URL из `quick_results.json` и добирает детальную информацию
- Данные: телефоны, сайты, часы работы, email
- Обогащает базовые данные из Quick режима
- Результат: `full_results.json` и `companies_2gis_full.csv`
- Использование: `python run_2gis_parser.py --url "..." --mode detail`

### Когда использовать двухфазный сбор

**Сценарий 1:** Быстрая разведка рынка
```bash
# Шаг 1: Быстро собираем все компании (только карточки)
python run_2gis_parser.py \
  --url "https://2gis.ru/moscow/search/ресторан" \
  --mode quick \
  --max-companies 5000

# Анализируем quick_results.json, фильтруем по рейтингу/отзывам
# Шаг 2: Добираем детали только для отфильтрованных компаний
python run_2gis_parser.py \
  --url "https://2gis.ru/moscow/search/ресторан" \
  --mode detail \
  --max-companies 1000
```

**Сценарий 2:** Экономия прокси-трафика
```bash
# Quick режим потребляет в 3-4 раза меньше запросов
python run_2gis_parser.py \
  --url "https://2gis.ru/kazan/search/автосервис" \
  --mode quick

# Детали собираем только для нужных компаний
python run_2gis_parser.py \
  --url "https://2gis.ru/kazan/search/автосервис" \
  --mode detail \
  --max-companies 500
```

**Сценарий 3:** Распределенный сбор
```bash
# Машина 1: Быстрый сбор всех URL
python run_2gis_parser.py --url "..." --mode quick

# Копируем quick_results.json на несколько машин
# Машина 2-5: Параллельный сбор деталей
python run_2gis_parser.py --url "..." --mode detail --max-companies 250
```

### Сравнение режимов

| Режим | Скорость | Данные | Прокси-трафик | Применение |
|-------|----------|--------|---------------|------------|
| Full | ~570/час | Все поля | Высокий | Полный сбор за один проход |
| Quick | ~2000/час | Базовые поля | Низкий | Разведка, фильтрация |
| Detail | ~800/час | Детальные поля | Средний | Обогащение отфильтрованных данных |

## Параллельный режим (ускорение в 3-5 раз)

Парсер поддерживает параллельный сбор с несколькими браузерами одновременно.

### Использование

Добавьте флаг `--parallel N`, где N - количество параллельных worker'ов:

```bash
python run_2gis_parser.py \
  --url "https://2gis.ru/kazan/search/автосервис" \
  --parallel 3
```

### Как это работает

1. **Этап 1:** Сбор всех URL компаний из поисковой выдачи (последовательно)
2. **Этап 2:** Параллельная обработка URL несколькими worker'ами
3. Каждый worker запускает свой браузер и использует свой прокси
4. Результаты собираются в общий список потокобезопасно

### Рекомендации

- **3 worker'а** - оптимально для большинства случаев
- **5 worker'ов** - для мощных машин и быстрых прокси
- **Больше 5** - может привести к блокировкам и перегрузке

### Производительность

| Режим | Компаний/час | Ускорение |
|-------|--------------|-----------|
| Последовательный (1 worker) | ~570 | 1x |
| Параллельный (3 worker'а) | ~1500-1700 | 3x |
| Параллельный (5 worker'ов) | ~2500-2800 | 5x |

### Примеры

Параллельный сбор с resume:

```bash
python run_2gis_parser.py \
  --url "https://2gis.ru/moscow/search/ресторан" \
  --parallel 3 \
  --resume \
  --max-companies 1000
```

Параллельный сбор с прокси:

```bash
python run_2gis_parser.py \
  --url "https://2gis.ru/spb/search/кафе" \
  --parallel 5 \
  --proxy http://proxy1.com:8080 \
  --proxy http://proxy2.com:8080 \
  --proxy http://proxy3.com:8080
```

**Важно:** Количество прокси должно быть >= количества worker'ов для оптимальной работы.

## Реальный кейс

Клиент заказал базу автосервисов в 5 городах (Москва, Санкт-Петербург, Казань, Екатеринбург, Новосибирск) для обзвона с предложением B2B услуг. Требования: название, адрес, телефон, рейтинг выше 4.0.

Ручной сбор через интерфейс 2ГИС: 40 часов работы, высокий риск ошибок при копировании.

Результат парсера: база собрана с полными контактами за несколько часов работы (в зависимости от объема). Экономия времени: в десятки раз быстрее ручного сбора. Данные экспортированы в Excel с фильтрацией по рейтингу. Клиент получил готовую базу для холодных звонков в тот же день.

**Производительность:**
- С детальным сбором (`--detail`): ~570 компаний/час
- Без детального сбора (`--no-detail`): ~1500-2000 компаний/час (без телефонов и сайтов)

## Устранение неполадок

### Ошибка: IP заблокирован

Симптомы: HTTP 403, HTTP 429, капча на странице.

Решение:
1. Убедитесь, что прокси настроены (через `--proxy`, переменную окружения или `config_2gis.py`)
2. Проверьте работоспособность прокси: `curl -x http://proxy:port http://2gis.ru`
3. Увеличьте задержки в `DELAYS` (config_2gis.py)
4. Используйте ротацию прокси
5. Проверьте переменную окружения `HTTP_PROXY` для системного прокси

### Ошибка: селекторы не найдены

Симптомы: пустые результаты, N/A в полях.

Решение:
1. Проверьте актуальность селекторов в `config_2gis.py`
2. Запустите парсер с `headless: False` для визуальной отладки
3. Проверьте логи в `output_2gis/parser_2gis.log`
4. Сделайте скриншот страницы (автоматически сохраняется при ошибках)

### Ошибка: таймаут загрузки страницы

Симптомы: TimeoutError, страница не загружается.

Решение:
1. Увеличьте таймауты в `TIMEOUTS`
2. Проверьте скорость прокси
3. Используйте режим `wait_until="commit"` вместо `networkidle`

### Рекомендации по User-Agent

Используйте актуальные User-Agent строки для Chrome/Firefox. Пример в `config_2gis.py`:

```python
"user_agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36"
```

Периодически обновляйте версию браузера в строке.

### Рекомендации по задержкам

Для снижения риска блокировки:
- Минимальная задержка между запросами: 3 секунды
- Рекомендуемая задержка: 5-8 секунд
- При сборе более 1000 компаний: увеличьте до 10-15 секунд

## Поля данных

Результирующие файлы содержат следующие поля:

| Поле | Описание | Пример |
|------|----------|--------|
| name | Название компании | Автосервис Премиум |
| address | Полный адрес | г. Казань, ул. Победы, 125 |
| category | Категория/рубрика | Автосервис |
| rating | Рейтинг (0-5) | 4.7 |
| reviews_count | Количество отзывов | 342 |
| phones | Телефоны (через запятую) | +7 (843) 555-1234 |
| website | Веб-сайт | https://example.com |
| hours | Часы работы | Ежедневно 09:00-21:00 |
| url | URL карточки на 2ГИС | https://2gis.ru/kazan/firm/123456 |
| parsed_date | Дата и время парсинга | 2026-05-01 14:23:15 |

Значение N/A указывает на отсутствие данных.

## Использование в Python

Пример программного использования с передачей прокси:

```python
import asyncio
import os
from parser_2gis import GisParser
from config_2gis import PARSING_CONFIG, PROXY_CONFIG

async def main():
    # Способ 1: Настройка прокси через переменную окружения
    os.environ["PROXY_LIST"] = "http://user:pass@proxy1.com:8080,http://proxy2.com:3128"
    
    # Способ 2: Настройка прокси через конфигурацию
    PROXY_CONFIG["enabled"] = True
    PROXY_CONFIG["proxies"] = [
        "http://user:pass@proxy.example.com:8080"
    ]
    
    # Настройка лимитов
    PARSING_CONFIG["max_companies"] = 100
    PARSING_CONFIG["max_pages"] = 5
    PARSING_CONFIG["open_detail_page"] = True
    
    # Запуск парсера
    parser = GisParser("https://2gis.ru/kazan/search/автосервис")
    await parser.run()
    
    # Результаты доступны в parser.companies
    print(f"Собрано компаний: {len(parser.companies)}")
    
    # Доступ к данным
    for company in parser.companies[:5]:
        print(f"{company['name']}: {company['phones']}")

if __name__ == "__main__":
    asyncio.run(main())
```
